## Licence position (verified 2026-10-21)

- Every asset below was opened on its own Pexels page; each shows the **"Free"** label linking to https://www.pexels.com/license/.
- Licence text (verbatim): "All photos and videos on Pexels can be downloaded and used for free." "You can modify the photos and videos from Pexels." "Attribution is not required." Prohibited: redistributing on "other stock photo or wallpaper platforms", selling unaltered copies, trademark use, implying endorsement, showing people in a bad light.
- **Uncertainty to flag:** the licence does not mention open-source software or public repositories. Bundling resized photos inside an MIT-style card is not a stock/wallpaper platform, which is the closest prohibition, but it is also not expressly permitted. Status of all assets is therefore **approved-with-caveat**, not unconditional. Risk reducers: ship resized, cropped, compressed copies only; do not publish originals or a browsable gallery; keep this attribution file; consider contacting Pexels support for a written answer. If that risk is unacceptable, the fallback is Wikimedia Commons CC0/public-domain images (clear redistribution rights) or the existing SVG illustrations.
- Attribution is optional; credit is listed here anyway. Two photographers *ask* (not require) for a link or a note (outdoors-1, outdoors-2).
- Not covered by the licence and not cleared: logos or artwork visible inside photos. Items to eyeball are noted below. No person releases are held; people are identifiable in some photos (marked), so avoid captions implying endorsement.
- Source access: Pexels and Unsplash scripted search/API returned 401/403, so candidates were found through page fetches and viewed locally. Unsplash was **not** used (no per-asset verification possible). Wikimedia Commons was not needed for this pass. Photographer names come from each photo page, not from filenames.

## Licensing review before integration (2026-10-21): BLOCKED

Integration is on hold. Findings from the official pages:

- **Permitted:** using the photos in an app UI, modifying them, no attribution ([license](https://www.pexels.com/license/)).
- **Prohibited:** redistributing on stock-photo or wallpaper platforms; selling unaltered copies.
- **Terms of Service ([terms](https://www.pexels.com/terms-of-service/), section 5):** the licence is non-exclusive and conditional on avoiding Prohibited Uses, including distributing content on a "standalone basis". A Pexels search snippet of the help centre defines standalone as content "substantially the same", for example only resized or cropped. The help-centre pages returned HTTP 403, so that definition is unconfirmed first-hand.
- **Not addressed anywhere I could read:** open-source repositories or bundling in redistributed software. The terms also disclaim model, property and brand releases ("AS IS").
- **Why it is material:** the 39 files would be resized or cropped copies, still substantially the same photographs, and a public repo makes each one a downloadable standalone file under an open-source licence that invites copying. That is the situation the standalone clause targets, and the project cannot sublicense the photos.

Resolution options: (1) ask Pexels support for written permission for this exact use; (2) replace with CC0/public-domain photographs (Wikimedia Commons, or Pexels/Unsplash images individually marked CC0); (3) keep the SVG illustrations. Nothing was integrated, bundled or committed.

## Recommended integration approach (not implemented)

1. **Keep the engine's category as the first key.** Photography is only a final tier: real event photo, then category photo, then the existing SVG illustration. The card still draws the illustration if the photo fails to load.
2. **Subject routing inside a category** from existing signals, with a fixed table: food gets `farmers-market` only when the title/tags match farmers/farm/produce/market-stall terms, `food-truck` for food truck/truck, and `restaurant` otherwise; other categories use their set. When the classifier is `general` or the strength is `none`, use the `general` set, never a guess.
3. **Deterministic variety, no randomness:** index = stable hash of the event id (or source-url hash) modulo the set size. The same event always shows the same photo across refreshes and devices. To reduce visible repetition within one list, offset by the event's position among same-category events so adjacent tiles differ.
4. **Ship small:** resized (about 640 px wide, JPEG q75-80, ~40-80 KB each, ~2-3 MB total) inside the integration's frontend folder, served from the static path. No hotlinks or runtime APIs. Include this attribution file in the repo and a short credits note.
5. **Theme fit:** apply a CSS overlay gradient behind tile text so photos work in both light and dark themes; dim slightly in dark mode.
6. **Gate on the licence question** above before merging any binaries.
